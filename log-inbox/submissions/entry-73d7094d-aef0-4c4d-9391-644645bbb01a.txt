Research note: GCP Compute Engine “Enable display device” does not provide a useful path for the current AL Cloud development VM. Google Cloud documentation says virtual displays are intended for guest-OS display-dependent applications such as remote desktop and screen capture, do not provide GPU performance, and are not supported on T2A Arm VMs. The active GCP development VM azl-android-arm64-01 is T2A ARM64, so this setting should not be relied on for the Android/ReDroid browser-streaming path. The current ReDroid capture architecture remains Android screenrecord -> localhost browser stream. Recommendation: leave the setting out of the design; it can be disabled while the VM is stopped to keep configuration minimal, though enabling it should not change the qualified Android capture approach.
