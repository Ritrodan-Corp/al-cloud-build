Recovered a prior project plan directly relevant to the current 4-OCPU / 1280x720 performance investigation.

Historical work had already identified a minimal custom Android SwiftShader/Pastel build as the preferred narrow rebuild path. The exact source target was android-14.0.0_r45 SwiftShader, with the Android Soong module vulkan.pastel producing /vendor/lib64/hw/vulkan.pastel.so. The earlier experimental patch would have removed the automatic llvm_shutdown_obj in LLVMReactor.cpp to test a renderer-lifetime hypothesis while keeping the rest of SwiftShader unchanged. The project record also explicitly proposed determining the smallest AOSP/ReDroid checkout capable of building only the ARM64 vulkan.pastel module.

Later Experiments 156-157 showed the original renderer teardown fault was secondary to an application-requested exit caused by the old LuaJIT lightuserdata limit, and the 39-bit low-VA solution removed that compatibility blocker. Therefore the old llvm_shutdown_obj suppression should not be carried forward as a production change without new evidence. However, the minimal Pastel build-path work is directly reusable for the new performance goal: establish a reproducible stock-equivalent vulkan.pastel control build, then produce separately versioned performance candidates that change only well-justified SwiftShader/Reactor optimization settings and benchmark them at the required 1280x720 geometry on the existing 4-OCPU Oracle A1 host.
