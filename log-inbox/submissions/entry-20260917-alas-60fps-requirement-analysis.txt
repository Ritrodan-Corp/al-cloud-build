2026-09-17: Reviewed upstream LmeSzinc/AzurLaneAutoScript source to determine whether ALAS technically requires Azur Lane at 60 FPS. Upstream README explicitly instructs users to set Frame Rate Settings = 60 FPS, but no code-level hard 60-FPS check or frame-count timing dependency was found. ALAS screenshot acquisition is timer-based, not frame-count-based: module/device/screenshot.py enforces a configurable minimum screenshot interval, normally clamped to 0.1-0.3s, with generated config default Optimization_ScreenshotInterval=0.3s and Optimization_CombatScreenshotInterval=1.0s. Input gestures are also duration/time based rather than tied to display refresh; module/device/control.py uses explicit time durations for clicks/swipes/drags. README known issues warn that low-end/slow emulators can have >1s screenshot cost and that emulator stalls can cause swipes to be treated as clicks. Current interpretation: 60 FPS is a robustness/performance recommendation intended to make UI transitions, animations, touch handling, and screenshot-visible state progression faster and less variable, not an architectural requirement that ALAS sample or process 60 frames/sec. 1280x720 remains a hard code-level requirement. This means AL Cloud can plausibly target stable automation below 60 FPS, subject to empirical ALAS validation.
