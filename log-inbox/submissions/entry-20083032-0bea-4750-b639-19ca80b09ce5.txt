Oracle FPS diagnostics renderer check identified the root VM-side bottleneck. SurfaceFlinger reports GLES as ANGLE over Vulkan on SwiftShader Device (LLVM 10.0.0), i.e. CPU software rendering rather than hardware GPU acceleration. ReDroid reports ro.boot.redroid_gpu_mode=guest, ro.hardware.egl=angle, and ro.hardware.vulkan=pastel. This aligns with the prior thread sample where four game threads each consumed ~93-94% of a CPU core. Conclusion: the logged-in home screen is primarily limited by CPU software graphics, yielding ~16.1 FPS without streaming; active H.264 streaming adds contention and reduced measured presentation to ~14.8 FPS. Next engineering focus should be improving the graphics path or provisioning additional CPU before tuning stream resolution/bitrate.
