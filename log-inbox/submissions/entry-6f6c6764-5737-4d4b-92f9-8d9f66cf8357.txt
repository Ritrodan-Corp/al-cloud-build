Set-chat-agent guidelines status review. Established operating guidance for fixed-time scheduled chat agents: use a one-shot scheduled invocation for clock-driven daily/reset chores; do not assume any automatic rerun after the invocation ends; within the single run, verify postconditions after each meaningful action, allow only bounded in-run correction/re-observation, fail closed on ambiguous or risky actions, and continue unrelated safe chores where possible. The likely first implementation is one Daily Reset routine covering reset-time chores such as login rewards, skill training, exercises as scheduled, daily raids, campaign hard attempts, dorm refill, and shop checks. The routine should read current account goals/policies before making strategic selections such as shop purchases or skill-training targets. Any completion record is audit/reporting only, not a retry mechanism. Not yet finalized: exact agent split versus one consolidated routine; exact step order; task-specific success/postcondition checks; purchase/spending rules; skill-training target policy; exercise cadence; exact schedule/time zone; model/reasoning configuration; worker-facing tool surface beyond the current azl-agent observation primitive; reporting schema; and a live proof that an unattended scheduled chat invocation can reliably control the Android session for these actions. Current status: architecture-level guidelines are established, but the detailed per-task SOP/prompt and production qualification remain to be written and tested.
