Agent-control architecture planning refinement: user clarified the desired end state is a high-level delegator agent that interprets strategic goals such as farm cubes, farm oil, level a named ship, or pursue a particular research-equipment target, then manages time-aware execution through narrower task agents. The design direction should therefore prioritize the intelligence/control plane before macro optimization.

Recommended architecture: separate strategic reasoning from temporal execution. A main delegator/director agent has broad Azur Lane knowledge plus account policy and converts user goals into weighted objectives, constraints, and subgoals. A deterministic shared scheduler/state store, rather than the language model, owns exact clocks, deadlines, completion timestamps, and wake events. Narrow agents receive only their task-specific knowledge plus relevant account state and goals, while retaining full-screen visual access for their bounded workflow. Candidate specialists include Tactical Class, commissions, Dorm/morale, sortie/leveling, and research agents.

The shared account-state layer should record known resources, current goals, assignments, active timers, expected completion times, observed/estimated morale, last-observed timestamps, confidence/freshness, and task outcomes. Timer types include exact UI-derived deadlines (Tactical training, commissions, research), modelled thresholds (for example estimated morale readiness, with periodic reconciliation), and uncertain/periodic checks. The scheduler should coalesce nearby events when lateness cost permits and invoke the relevant specialist at the useful time. Specialists update shared state and may return a next-useful-check time.

Important deployment implication: short dynamic timers should not rely solely on ChatGPT recurring Scheduled Tasks. The intended Oracle Always Free host can eventually keep a lightweight local scheduler running continuously, which is ideal. During paid GCP development, an external wake mechanism is still required whenever the VM is stopped. Preserve the existing goal of proving ordinary ChatGPT Scheduled Task -> Remote Desktop Commander invocation, but treat Scheduled Tasks primarily as high-level/external wake triggers rather than the sole fine-grained timing engine unless later acceptance proves dynamic one-off scheduling practical.

Feasibility assessment: high for exact-timer activities such as Tactical Classes and commission completions; high for commission choice once the specialist has full-screen perception and a policy objective such as favor cubes/oil; medium-high for Dorm morale tracking if morale can be observed or conservatively estimated and periodically reconciled; medium for end-to-end 'level ship X' because it combines Dorm placement, morale, fleet/stage selection, resource floors, and repeated sorties; medium-high for research-equipment farming if the agent has a curated mapping from target equipment to relevant research choices and current project/queue state. Biggest engineering risks are perception robustness, current knowledge/event drift, account-state freshness after human play, safe wake/start/stop behavior, and inter-agent coordination, not the basic multi-agent decomposition itself.

Proposed hierarchy: user goals -> delegator/director -> shared policy/state + deterministic scheduler -> narrow task agent -> common visual/control interface -> ReDroid/Azur Lane. The delegator should wake mainly when goals change, specialists report conflicts/unknown states, or strategic reprioritization is needed; routine timer expirations should invoke the relevant specialist directly. Macros remain a later optimization beneath specialist agents for deterministic navigation, not the primary intelligence layer.
