Scheduling synthesis for fixed AL Cloud chat agents. Proposed baseline is three daily maintenance runs, not seven, centered on an 8-hour T3 Tactical Class cadence. Candidate phase: approximately 07:15, 15:15, and 23:15 server time. This phase lets each run fall inside a distinct General Shop inventory window (00-12, 12-18, 18-24), so each shop cycle can be checked once near the end of its validity window rather than at refresh. Exercise attempts can be consumed only on the first and last runs: after the 23:15 spend, 00:00 adds 5; 07:15 spends 5; 12:00 and 18:00 add 10 total; 23:15 spends 10, avoiding cap loss. The 07:15 run becomes the main daily-reset batch for Hard 13-4, daily raids, guild logistics, daily/weekly/monthly shop work, dorm maintenance, and other daily claims. 15:15 and 23:15 are lighter maintenance runs. Commission and research checks should piggyback on these fixed runs, while any future variable-timer architecture may handle finer-grained completion timing separately. Guild Operation dispatch timing requires one remaining production verification: external references indicate dispatch capacity accrues at 00:00/06:00/12:00/18:00 and multiple accrued fleets can be sent during a later login, with a maximum of four fleets; this is older evidence and should be verified in the current EN client before relying on coalesced 07:15/15:15/23:15 checks. Prior assumption that 21:00 is a Guild Operation dispatch refresh was incorrect; ALAS uses a 21:00 guild scheduler poll, but that is not evidence of a game-side dispatch refresh. Tactical fixed scheduling also needs bounded in-run handling for execution latency: check Tactical early, do other assigned chores if an 8-hour lesson has a few minutes remaining, then re-check/wait briefly within the same invocation rather than assuming exact second-level completion.
