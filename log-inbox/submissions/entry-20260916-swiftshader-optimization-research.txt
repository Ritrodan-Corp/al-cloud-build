Completed fixed-resource performance research for Oracle PAYG A1 at 4 OCPUs and mandatory 1280x720. Live simpleperf sampling of Azur Lane showed ~90% of sampled cycles in anonymous JIT-generated code executed by SwiftShader's four Marl worker threads; call chains resolve through vk::Queue/vk::CommandBuffer/sw::Renderer::draw and vulkan.pastel.so, while Unity main/game logic is comparatively light. No Android game-mode intervention is applied, hot renderer/Unity threads can use CPUs 0-3, uclamp.max is unrestricted, and the VM exposes no guest cpufreq/governor controls. ALAS upstream hard-rejects non-1280x720 screenshots and recommends Azur Lane Frame Rate Settings = 60 FPS. Live PlayerPrefs currently show Unity resolution 1280x720 and fps_limit=30; ReDroid is also booted at 30 Hz. Presentation timing is mostly 66.7 ms with occasional 33.3 ms frames, consistent with missing 30 Hz deadlines and falling to every second vsync. Research rejects forcing the deprecated direct SwiftShader GLES frontend: upstream recommends ANGLE-over-SwiftShader Vulkan and ReDroid users report instability forcing the old path. Candidate zero-cost optimization order: (1) controlled ReDroid 60-Hz display experiment while initially retaining game fps_limit=30 to test whether finer vsync cadence reduces the 66.7-ms quantization penalty without increasing game target workload; (2) remove optional in-game visual effects that do not affect ALAS recognition, noting battleHideBg=1 is already enabled while show_touch_effect and display_ship_get_effect remain enabled; (3) if needed, build a disposable optimized SwiftShader variant, focusing on Reactor JIT optimization / newer SwiftShader rather than merely changing static -Os compiler flags because JIT code dominates cycles; ARM64 cannot use the Subzero backend, so LLVM remains required; (4) continue treating browser encoding as a secondary load because prior measurement showed streaming reduces game presentation from ~16.1 to ~14.8 FPS. Any restart-based experiment must first protect the logged-in Android /data state. No production settings changed during this research pass.
