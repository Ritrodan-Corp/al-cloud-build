Cloudflare controller-access design research checkpoint. Preferred future design: keep AL Cloud browser controller bound to VM loopback 127.0.0.1:8766; run ARM64 cloudflared as a Linux system service on the VM; create a remotely-managed Cloudflare Tunnel publishing a dedicated HTTPS hostname to http://127.0.0.1:8766; protect that hostname with Cloudflare Access before publishing the tunnel route; enable tunnel-side Access token validation/Protect with Access for defense in depth. For the H.264 chunked stream path, retain Cache-Control: no-store/no-transform and add a narrow Cloudflare Configuration Rule for /stream.h264 with Response Body Buffering=None if testing shows standard buffering adds latency. Same-origin Access cookies should cover page, API calls, and stream fetch transparently. Controller should detect Access/session expiry and present a reconnect/re-auth prompt. This approach removes per-device IAP/PowerShell setup, preserves no inbound VM ports, works on desktop/mobile, and should migrate cleanly from GCP to Oracle because the public hostname remains decoupled from host IP.
