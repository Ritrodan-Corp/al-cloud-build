Oracle browser-streaming watchdog design: reviewed the deployed browser client/server logic. app.js reconnects only after the /stream.h264 HTTP body ends or errors; it has no no-frame timeout. azl_stream_server.py waits indefinitely while screenrecord remains alive, even if stdout stops producing bytes. Therefore a screenrecord instance that emits one IDR then hangs can leave the browser at 0 fps forever. Chosen fix: add a server-side producer-silence watchdog that ends a stream when screenrecord stdout has no bytes for a configurable short interval after output has started. The existing browser reconnect loop will then obtain a fresh encoder automatically. Validate at existing 854x480/2Mbps before separately changing to native 1280x720.
