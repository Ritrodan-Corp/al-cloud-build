Completed research pass on Azur Lane's in-game Rendering Compatibility Mode and its applicability to AL Cloud.

Findings: Yostar's official 2025-09-29 Island Planner maintenance notice explicitly directs users with display faults such as screen flickering to enable Rendering Compatibility Mode under Main Menu -> Settings -> Options -> Other Settings. The same notice separately tells emulator users to set the emulator graphics renderer to OpenGL and, for artifacts, to disable Distortion in Island settings. A Chinese community report from 2025-09-04 also reports the in-game Rendering Compatibility Mode as a fix for split-screen/small-window black screens. Public documentation and public GitHub code search did not expose the toggle's internal implementation, serialized key, shader path, or exact graphics-API effect.

Technical interpretation for AL Cloud: the toggle is applicable as a secondary display-compatibility/usability control, especially for flicker, black-screen, distortion, or special 3D/Island content. It is not evidence of a replacement for the qualified 39-bit host kernel or package-scoped native-heap-tagging override, because those solve the independently proven LuaJIT 2.1.0-beta3 high-address lightuserdata failure. It also should not be assumed to bypass ANGLE/Pastel or force OpenGL/GLES. Yostar treats emulator renderer selection as a separate instruction, and Unity's Android graphics API selection is governed by the built application's configured graphics API list/startup selection. Current AL Cloud already renders and completes representative autoplay on the stock ANGLE/Pastel path under Experiment 157, so the main present weakness is CPU-saturated interactive responsiveness/transport rather than a display-compatibility failure.

Recommendation: do not change the working persistent configuration solely because this mode exists. Keep it as a bounded A/B candidate if AL Cloud encounters rendering artifacts, Island/3D-specific faults, or if a controlled test is desired to see whether it incidentally reduces software-renderer cost. A useful A/B would hold kernel, ReDroid, data, FPS, CPU cap, and scene constant; toggle only Rendering Compatibility Mode; then compare renderer identity/logs, screenshots/artifacts, SurfaceFlinger cadence, container CPU/memory, and any restart requirement. Do not infer a backend change without direct evidence. Remote Desktop Commander was unavailable during this research pass, so no VM start, Android mutation, game launch, or toggle change was performed.
