Browser streaming live-source qualification: exact ReDroid Android 14 screenrecord v1.3 binary supports hidden `--output-format=h264` stdout mode even though its help text omits the option. `adb -s 127.0.0.1:5555 exec-out screenrecord --output-format=h264 --size 854x480 --bit-rate 2000000 --time-limit 8 -` produced a 1,274,795-byte Annex-B stream while Azur Lane MainActivity was foreground. NAL sequence contained one SPS (type 7), one PPS (8), one IDR (5), and 237 non-IDR VCL NALs (1), 240 NALs total over 8 seconds, consistent with about 30 coded pictures/sec and one VCL NAL per picture in this probe. SPS began `67 42 c0 29`, giving AVC codec string avc1.42c029. Host ffmpeg is not installed, so implementation should avoid a remux dependency. Decision: use raw Annex-B H.264 directly with browser WebCodecs as the first low-overhead path; preserve existing localhost HTTP control API and keep PNG polling as fallback. Temporary probe files were removed and Android was returned to Launcher. No display/service/baseline settings were changed.
