Preliminary research pass on Azur Lane Rendering Compatibility Mode and applicability to AL Cloud. Official Yostar maintenance guidance for Island Planner states that users who encounter display issues such as screen flickering should enable Rendering Compatibility Mode under Main Menu -> Settings -> Options -> Other Settings. The same official notice separately recommends OpenGL as the emulator graphics renderer and lowering Island graphics settings for frame drops/lag. Chinese official-derived notices repeat the same guidance. This establishes that Rendering Compatibility Mode is a first-party compatibility control aimed at display/rendering faults, not merely an emulator vendor setting.

Project-state comparison: current Experiment 157 already has the unmodified official client running successfully in-game on ReDroid with EGL=angle / Vulkan=pastel under the 39-bit low-VA kernel plus package-scoped native heap pointer tagging disable. The former LuaJIT startup blocker is solved, and the Oracle-like 2-vCPU/15-FPS C3 autoplay discriminator passed. Therefore Rendering Compatibility Mode should be evaluated, if at all, as a possible renderer-compatibility/performance/usability lever for the already-working software-rendered path, not as a fix for the old high-VA LuaJIT crash. Public documentation does not disclose what internal rendering/API behavior the toggle changes, so more investigation is needed before claiming it can replace ANGLE/pastel, the 39-bit kernel, or the pointer-tagging override. No VM, Android, game, or project runtime mutation was performed in this research step.
