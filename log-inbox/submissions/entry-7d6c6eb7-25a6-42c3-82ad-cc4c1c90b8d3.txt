2026-09-16 PDT — Issue #37 backfill: Oracle 39-bit kernel, ReDroid, and Azur Lane qualification
Workstream: Oracle migration / host-runtime compatibility
Source: https://github.com/Ritrodan-Corp/al-cloud-build/issues/37

Action/result: Backfilled durable runtime milestones that were written to issue #37 instead of the authorized immutable log intake.

Oracle host/runtime: after the durable RDC/Tailscale administration path was established, Docker and host ADB were installed. The stock Oracle kernel was `6.17.0-1018-oracle`, ARM64 with 4096-byte pages and 48-bit VA. A disposable stock ReDroid Android 14 ARM64 smoke runtime was created with loopback-only ADB. The exact Play-signed Azur Lane 9.3.7 base APK from the qualified GCP runtime was transferred to Oracle and hash-verified as SHA-256 `37b24bc2e299248377483fa67041c53cb9357534d9e5e6e24f248fc70da56734` before testing.

48-bit discriminator: under the stock 48-bit Oracle host, Azur Lane reproduced the prior rapid Pastel/LLVM abort family, while live process mappings were observed far above the 39-bit userspace ceiling. The stable GCP reference on `6.8.12-exp157-39va` retained mappings below `0x8000000000`. This strongly correlated the Oracle failure with the 48-bit userspace layout and justified a reversible low-VA host-kernel test.

Custom kernel: built `6.8.12-alcloud39` from Canonical/Ubuntu Oracle 6.8.0-1060.63 source seeded with the exact 6.8.0-1060-oracle config, changing ARM64 VA from 48 to 39 bits while retaining 4 KiB pages and required OCI/container/ReDroid features. The build completed successfully. A first install attempt produced an oversized unstripped 7.6 GiB module tree and failed initramfs generation for lack of `/boot` space; no reboot or GRUB selection occurred. The module tree was then stripped and explicitly zstd-compressed to 177 MiB, initramfs generation succeeded, and GRUB retained the signed `6.17.0-1018-oracle` fallback plus the custom entry. A one-shot `grub-reboot` test boot was used rather than changing the permanent default.

Boot qualification: the VM successfully booted `6.8.12-alcloud39`; page size remained 4096, `CONFIG_ARM64_VA_BITS_39=y`, and live process mappings stayed below the 39-bit ceiling. RDC, Tailscale, and Docker recovered. The temporary reboot watchdog was disarmed after validation. Binder remained available as a module. ReDroid initially failed because binderfs nodes were mode 0600; correcting binder device-node permissions allowed Android to reach `sys.boot_completed=1` with loopback ADB. This demonstrates that the custom 39-bit Oracle kernel supports a fully booted ReDroid Android 14 guest.

Azur Lane result: installed the exact hash-verified official 9.3.7 APK into the disposable Oracle ReDroid guest. Cold launch returned Status=ok and MainActivity remained top-resumed with one stable PID instead of the prior ~2-second crash loop. Recent log scans showed no `FORTIFY`, destroyed-mutex, `vulkan.pastel`, SIGABRT, or Fatal signal 6 sequence. This closes the old fatal Pastel/LLVM crash as the immediate Oracle blocker under the 39-bit kernel.

Current blocker/qualification boundary: the game is alive but the visible framebuffer remains black after dismissing Android's fullscreen tutorial. Unity logs indicate a dependency asset bundle is absent and should be downloaded. The stock ReDroid image lacks Google Play Services/Play Store, but existing evidence does not establish that Azur Lane itself requires Play Store at runtime; missing-Play warnings must not be treated as the root cause without further evidence. The Oracle install currently contains only the base APK and about 267 MiB total app/data footprint, far below the expected fully populated payload, with no large asset bundles present. Therefore Oracle is not yet a usable game runtime despite passing the low-VA crash discriminator and ReDroid boot gate.

Interpretation/next: Treat Oracle host/kernel compatibility as materially advanced: A1 4-OCPU/16-GB, 4-KiB pages, private administration, custom 39-bit boot, and ReDroid boot are all demonstrated. The active runtime blocker is now game asset provisioning/usable visible startup, not the prior fatal VA/Pastel crash. Preserve GCP as the qualified reference until Oracle reaches a usable title/login/gameplay state and billing/network/storage behavior are fully validated. Later substantive findings should use the normal immutable intake rather than issue comments.
