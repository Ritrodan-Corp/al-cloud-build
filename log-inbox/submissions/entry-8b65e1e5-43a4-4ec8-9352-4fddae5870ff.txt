Oracle A1 ReDroid GPU research checkpoint: upstream ReDroid documentation and source confirm host mode selects Mesa/GBM on a DRM render node and supports virtio_gpu, but a render node alone does not establish accelerated 3D. Read-only inspection of alcloud-a1-01 shows /dev/dri/renderD128 on virtio_gpu, while kernel debugfs reports `virgl: no`, `cap sets: 0`, `blob resources: no`, `context init: no`, and host allocations not visible to guest. This means the OCI A1 Virtio GPU lacks the VirGL/3D capabilities ReDroid host mode would need for useful acceleration; switching the production container to host mode is therefore no longer the preferred first optimization. Upstream issue history also documents host-mode failures on nested/virtio configurations and Azur Lane instability on some physical host GPUs. Next: treat current A1 as software-render-only, benchmark lower Android render resolutions and investigate CPU/shape alternatives before any destructive container change.
